# Лабораторная работа № 4 (СиФО ВМ) — Quartus II 9.1

Микропроцессорное устройство с раздельной памятью команд и данных,
устройством управления и блоком регистров общего назначения.

**Вариант:** ШД = **6** бит, ША = **4** бита,
команда 1 — **MOV M → R** (прямая адресация операнда-источника),
команда 2 — **JZ** (непосредственная адресация адреса перехода),
РОН — **4 регистра**.

| Параметр | Значение |
|---|---|
| Шина адреса (ША) | 4 бита → 16 ячеек |
| Шина данных (ШД) | 6 бит |
| ROM (память команд) | 16 × 8 бит, `rom.mif` |
| RAM (память данных) | 16 × 6 бит, `ram.mif` |
| РОН | R0…R3, по 6 бит |
| Слово команды | 8 бит: `КОП(2) │ ADR(4) │ R(2)` |
| Команды | `01` MOV M→R, `10` JZ, `11` JMP (резерв), `00` NOP |
| Спецрегистры (в УУ) | IP (4), IR (8), AR (4), DR (6), FR/Z (1), T (3) |

Подробно (АСК, коды команд, микропрограмма, таблица управляющих сигналов,
трасса по тактам) — в **[docs/ОТЧЕТ.md](docs/ОТЧЕТ.md)**,
структурная схема — **[docs/scheme.svg](docs/scheme.svg)**.

## Микропрограмма

```
00  MOV M[4], R0   ; R0 <- 0Ah   Z=0
01  JZ  $3         ; перехода нет
02  MOV M[5], R1   ; R1 <- 15h   Z=0
03  MOV M[6], R2   ; R2 <- 2Ah   Z=0
04  MOV M[7], R3   ; R3 <- 00h   Z=1
05  JZ  $0         ; переход на 00 (цикл)
```

Числовые коды: `50 8C 55 5A 5F 80`, далее `00` (NOP).

## Как собрать и промоделировать

1. Открыть `lab4.qpf` в Quartus II 9.1.
2. **Processing → Start Compilation**.
3. Открыть `lab4.vwf` → **Simulation → Run Functional Simulation**.

Контролировать сигналы: `clk`, `adr_out` (ША), `data_out` (ШД),
`ir_out` (регистр команд), `T_out` (номер такта), `flag_out` (флаг Z),
`ram_en_out`, `ron_wr_out`, `ron_addr_out`.

Ожидаемый результат: `R0 = 0A`, `R1 = 15`, `R2 = 2A`, `R3 = 00`,
далее — бесконечный цикл `00 → 05 → 00`.

## Замечания по реализации

* Все связи в схемах проведены **графически** — ортогональными проводниками
  (`connector`) от вывода к выводу, с узлами в точках ветвления. Имена цепей
  стоят только на **ответвлениях от шин** (`ir[5..2]`, `ir[7]`, `dr[3]` …),
  где иначе невозможно указать, какие разряды шины снимаются; имя хранится
  внутри самого проводника-отвода, как это делает Block Editor.
* Проводники не могут идти по одной линии, заканчиваться на чужом проводе или
  изламываться на нём (это было бы КЗ) — трассировщик `tools/router.py`
  проверяет это при прокладке, а `tools/check.py` — по готовому `.bdf`.
* Слово команды (8 бит) шире ШД (6 бит), поэтому ROM выдаёт команду в регистр
  команд IR по отдельной шине `rom_data[7..0]`. Адресные входы ROM и RAM
  подключены к одной ША, как требует задание.
* Сигналы `ram_wr` и `ron_rd` в текущей АСК не используются (выведены в 0
  и оставлены как резерв для команд `R→M` / `R+R`).

## Скрипты (`tools/`)

| Скрипт | Что делает |
|---|---|
| `sim.py` | цикловая модель АСК: прогон микропрограммы, трасса по тактам |
| `router.py` | трассировщик: ортогональная разводка проводников с учётом занятости |
| `make_schematics.py` | генерация `rom.bdf`, `ram.bdf`, `ron.bdf`, `uu.bdf`, `laba4.bdf` и `.bsf` |
| `make_vwf.py` | генерация `lab4.vwf` |
| `check.py` | проверка готовых схем: геометрия проводников сверяется с замыслом (связность, КЗ, подписи) |
| `render.py` | отрисовка `.bdf` в PNG (для быстрой визуальной проверки разводки) |
| `bdfgen.py` | мини-библиотека для сборки схем Quartus (`.bdf`/`.bsf`) |

Пересборка схем: `python3 tools/make_schematics.py`,
проверка: `python3 tools/check.py laba4.bdf uu.bdf ron.bdf ram.bdf rom.bdf`,
картинки для отчёта: `python3 tools/render.py uu.bdf laba4.bdf ron.bdf ram.bdf rom.bdf`
(результат — `docs/img/*.png`).
