# Шпаргалка к защите Л.Р. № 4

«Считывание, декодирование и выполнение команд. Способы адресации операндов»
Вариант: **ША = 6, ШД = 4**; первая команда — `MOV M → R` с **прямой** адресацией
операнда-источника; вторая — `JZ` с **непосредственной** адресацией адреса перехода.
Проект Quartus II 9.1 Web Edition, верхний уровень `laba4.bdf`.

---

## 1. Всё в двух строках

```
ША = 6 бит (64 ячейки)   ШД = 4 бита   РОН = 4 × 4 бита (R0…R3)
ROM = 64 × 9 (команды)   RAM = 64 × 4 (данные)   слово команды = 9 бит
```

`КОП = IR[8]` · `R = IR[7..6]` · `ADR = IR[5..0]`
`0` → `MOV Rr ← M[ADR]` (прямая) · `1` → `JZ ADR` (непосредственная, при `Z = 1`)

---

## 2. Почему именно такие разрядности (самый частый вопрос)

| Поле / узел | Разрядность | Откуда берётся |
|---|---|---|
| ША и поле `ADR` | 6 | задано вариантом: 2⁶ = 64 ячейки памяти |
| ШД, RAM, DR, РОН | 4 | задано вариантом: данные 4-битные |
| Поле `R` | 2 | РОН 4 регистра → 2² = 4 |
| Поле `КОП` | 1 | в АСК **две** команды → 2¹ = 2 кода |
| Слово команды, IR | 9 | 1 + 2 + 6 = 9 |
| IP, AR | 6 | адрес всегда равен разрядности ША |
| FR | 1 | один флаг `Z` |

**Почему команда (9 бит) шире ШД (4 бита):** в ней надо разместить КОП + номер
регистра + 6-битный адрес. Поэтому ROM выдаёт слово не на ШД, а по собственной
шине `rom_data[8..0]` прямо в регистр команд IR (так же, как в примере методички).

**Почему КОП один бит:** в задании ровно две команды. `JMP`/`NOP` не заказывались —
расширять АСК до 4 кодов и делать КОП 2 бита не нужно.

---

## 3. Формат команды

```
  8  │ 7  6 │ 5  4  3  2  1  0
─────┼───────┼──────────────────
 КОП │   R   │       ADR
 (1) │  (2)  │       (6)
```

* `КОП = 0` — `MOV`: `ADR` = **физический адрес операнда в RAM**, `R` = приёмник;
* `КОП = 1` — `JZ`: `ADR` = **адрес перехода** (в ROM), поле `R` не используется (`00`).

## 4. АСК

| КОП | Команда | Формат | Действие |
|---|---|---|---|
| `0` | `MOV M→R` | `0 R ADR` | `R ← M[ADR]`; `Z ← (M[ADR] == 0)` |
| `1` | `JZ $ADR` | `1 00 ADR` | если `Z = 1` → `IP ← ADR`, иначе `IP ← IP + 1` |

**Прямая адресация** (`MOV`): адрес операнда берётся прямо из поля `ADR` команды,
кладётся в `AR` и через мультиплексор идёт на ША. Никаких дополнительных
обращений к памяти за адресом нет.

**Непосредственная адресация** (`JZ`): адрес перехода находится непосредственно
в команде (`IR[5..0]`), он загружается в `IP` асинхронно, без выборки из памяти.

## 5. Программа

### 5.1 Символьно и в числах

| Адрес ROM | Символьно | BIN (9 бит) | HEX |
|---|---|---|---|
| `00` | `Mov ($4), R0` | `000000100` | `004` |
| `01` | `JZ $3` | `100000011` | `103` |
| `02` | `Mov ($5), R1` | `001000101` | `045` |
| `03` | `Mov ($6), R2` | `010000110` | `086` |
| `04` | `Mov ($7), R3` | `011000111` | `0C7` |
| `05` | `JZ $0` | `100000000` | `100` |

`$n` в `Mov` — адрес в **RAM**, в `JZ` — адрес в **ROM**.

### 5.2 Разбиение по полям

| Адрес | КОП | R1 | R0 | ADR5 | ADR4 | ADR3 | ADR2 | ADR1 | ADR0 |
|---|---|---|---|---|---|---|---|---|---|
| `00` | 0 | 0 | 0 | 0 | 0 | 0 | 1 | 0 | 0 |
| `01` | 1 | 0 | 0 | 0 | 0 | 0 | 0 | 1 | 1 |
| `02` | 0 | 0 | 1 | 0 | 0 | 0 | 1 | 0 | 1 |
| `03` | 0 | 1 | 0 | 0 | 0 | 0 | 1 | 1 | 0 |
| `04` | 0 | 1 | 1 | 0 | 0 | 0 | 1 | 1 | 1 |
| `05` | 1 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |

Картинка для отчёта: `docs/img/code_table.png`.

### 5.3 Данные в RAM (`ram.mif`)

```
04 : 9      05 : 6      06 : F      07 : 0      остальные : 0
```

### 5.4 Результат выполнения

`R0 = 9`, `R1 = 6`, `R2 = F`, `R3 = 0`, после чего `JZ $0` при `Z = 1` возвращает
`IP` на `00` — программа зацикливается: `00 → 05 → 00 → …`
Проверено моделью `tools/sim.py`: `RON = [9, 6, F, 0]`.

## 6. Микропрограмма: 8 тактов на команду (`T0…T7`, реально `T0…T4`)

**Выборка команды — общая:**

| Такт | Действие |
|---|---|
| `T0` | ША ← IP (мультиплексор в положении «IP»), ROM читает слово по адресу IP |
| `T1` | `IR ← ROM[IP]`, `IP ← IP + 1` |

**`MOV M → R`:**

| Такт | Действие |
|---|---|
| `T2` | `AR ← IR[5..0]` (поле ADR) |
| `T3` | ША ← AR, RAM выдаёт `M[AR]` на ШД, `DR ← ШД` |
| `T4` | `DR → ШД`, `R[IR[7..6]] ← ШД`, `FR.Z ← (DR = 0)` |

**`JZ $ADR`:**

| Такт | Действие |
|---|---|
| `T2` | декодирование (проверка `IR[8]`) |
| `T3` | если `Z = 1` → `IP ← IR[5..0]`; иначе `IP` остаётся `IP + 1` из такта `T1` |

## 7. Управляющие сигналы (ШУ)

`mov = ~IR[8]`, `jump = IR[8] & Z`

| Сигнал | Формула | Что делает |
|---|---|---|
| `sel_sha` | `T3 & mov` | источник ША: 0 — IP, 1 — AR |
| `ir_ld` | `T1` | запись IR из ROM |
| `ip_en` | `T1 + (T3 & jump)` | разрешение записи IP |
| `ip_jump` | `T3 & jump` | на вход IP — адрес перехода вместо `IP+1` |
| `ar_ld` | `T2 & mov` | запись AR из поля ADR |
| `ram_en` | `T3 & mov` | выдача RAM на ШД |
| `dr_ld` | `T3 & mov` | запись DR с ШД |
| `dr_out` | `T4 & mov` | выдача DR на ШД |
| `ron_wr` | `T4 & mov` | запись в РОН |
| `ron_addr[1..0]` | `IR[7..6]` | номер регистра РОН |
| `fr_ld` | `T4 & mov` | запись флага Z |
| `ram_wr` | `0` | в этой АСК не нужен (нет `R→M`), выведен в резерв |
| `ron_rd` | `0` | чтение РОН в тракт в этой АСК не нужно, резерв |

Флаг: `Z = NOT(DR[3] + DR[2] + DR[1] + DR[0])` — дерево из трёх `OR2` и одного `NOT`.

## 10. Порядок действий в Quartus

1. Открыть `lab4.qpf`.
2. **Processing → Start Compilation** — должно быть `0 errors`
   (проверено: синтез, fitter, assembler, timing — успешно).
3. Моделирование: открыть `lab4.vwf` → **Simulation → Run Functional Simulation**.
   Если `quartus_sim.exe` падает с `VDB_VALUE_BUS::is_homogenous` — открыть
   `lab4_bits.vwf` (там нет строк-шин, только отдельные разряды) и запустить
   моделирование по нему; оба файла генерируются `python3 tools/make_vwf.py`.
4. Смотреть сигналы: `clk`, `adr_out[5..0]` (ША), `data_out[3..0]` (ШД),
   `ir_out[8..0]` (что в IR), `T_out[2..0]` (такт), `flag_out` (Z),
   `ron_addr_out[1..0]`, `ron_wr_out`, `ram_en_out`, `rom_data_out[8..0]`.
5. Что должно быть видно: на `adr_out` поочерёдно `00 → 01 → 02 → 03 → 04 → 05`
   (выборка команд), затем `04, 05, 06, 07` (чтение операндов по прямой адресации)
   и возврат на `00`; `flag_out` становится 1 после чтения `M[7] = 0`;
   в конце — переход `JZ $0`.

Регистры сброса не имеют, при функциональном моделировании стартуют с нуля
(`IP = 0`, `T = 0`) — программа идёт с адреса `00`.

## 11. Предупреждения компилятора — что отвечать

| Предупреждение | Что сказать |
|---|---|
| `ron_rd_out` / `ram_wr_out` **stuck at GND** | в этой АСК нет команд `R→M` и чтения РОН в тракт, поэтому `ram_wr` и `ron_rd` не используются и выведены в 0 (резерв под расширение АСК) |
| `12 registers lost all their fanouts` (РОН) | выходы РОН идут на выводы `data_out` только через `lpm_bustri`, а его вход `enabledt` = 0; логика записи в РОН при этом работает (видно по `ron_wr_out` и `ron_addr_out`) |
| `No exact pin location assignment` | для функционального моделирования физические номера выводов не нужны; при необходимости задаются в Pin Planner |
| `Port "data_a" ... width 8 vs 9` | это вход записи ROM, который для ROM не используется (`wren_a = 0`); исправлено на 9 бит в `lpm_rom0.v` |

## 12. Вопросы на защите и короткие ответы

1. **Сколько бит слово команды и почему?** 9 = КОП(1) + R(2) + ADR(6).
2. **Почему КОП 1 бит?** В АСК две команды: `MOV` и `JZ`.
3. **Почему ADR 6 бит?** Разрядность ША = 6, память на 64 ячейки.
4. **Чем прямая адресация отличается от косвенной?** При прямой адрес операнда
   указан в команде и сразу идёт на ША; при косвенной в команде адрес ячейки,
   где лежит **адрес** операнда, — нужна дополнительная выборка.
5. **А непосредственная?** Адрес перехода записан прямо в команде; при `Z = 1`
   он загружается в IP, без обращений к памяти.
6. **Зачем AR, если адрес есть в IR?** Чтобы поле ADR команды не «портилось»
   и чтобы ША управлялась мультиплексором IP/AR единообразно.
7. **Зачем DR?** Данные из RAM приходят в такте `T3`, а писать в РОН надо в `T4`;
   DR — это буфер между ШД и РОН, а заодно источник флага Z.
8. **Почему ROM не на ШД?** Слово команды 9 бит, а ШД 4 бита — не помещается.
9. **Как формируется Z?** `Z = NOT(DR3+DR2+DR1+DR0)`, пишется в FR в `T4`
   команды `MOV`, проверяется в `T3` команды `JZ`.
10. **Сколько тактов на команду?** 8 (`T0…T7`), реально нужны `T0…T4`.
11. **Как выбирается регистр РОН?** `ron_wr` + `ron_addr[1..0] = IR[7..6]`,
    дешифратор 2→4 выдаёт разрешение записи нужному регистру.
12. **Как реализована память?** Мегафункции `LPM_ROM` (64×9) и `LPM_RAM_DQ`
    (64×4), содержимое задаётся `rom.mif`/`ram.mif` при компиляции.
13. **Что делает `sel_sha`?** Переключает ША: при выборке команды — `IP`,
    при обращении к операнду — `AR`.
14. **Что будет при `Z = 0` в `JZ`?** Перехода нет, `IP` уже увеличен на 1
    в такте `T1` — выполняется следующая команда.
15. **Почему в программе два `JZ`?** Чтобы показать оба исхода: `JZ $3`
    при `Z = 0` (перехода нет) и `JZ $0` при `Z = 1` (переход есть, цикл).

## 13. Ограничения и честные оговорки

* В АСК две команды, поэтому `ram_wr` и `ron_rd` не задействованы — это задел
  под расширение (например, `R → M`).
* Ячейки ROM `06…3F` содержат нули, что формально декодируется как
  `MOV M[0], R0`; до них управление не доходит — программа заканчивается
  `JZ $0`.
* Содержимое РОН не выведено на внешние выводы (буфер РОН всегда закрыт);
  значения РОН проверены моделью `tools/sim.py`, а в схеме — через `ron_wr`/
  `ron_addr`. Если нужно видеть РОН на выводах `data_out` — вход `enabledt`
  буфера РОН надо подключить к 1 вместо земли.
